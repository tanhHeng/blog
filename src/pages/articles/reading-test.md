## 一、为什么要自己搭一个博客

现成的平台很多，但它们大多把「写作」和「呈现」拆开：你只负责文字，版式交给模板。而我想要的恰恰相反——希望**每一页都像一张被认真排过的版面**，留白、字号、颜色和动效都服务于阅读本身。

所以这个站点从一开始就有几条约束：

1. 静态生成，不依赖服务器、数据库或 CMS；
2. 视觉上保持克制：蓝色调、衬线字体、大量留白；
3. 交互只在**无法用 HTML/CSS 实现**时才写脚本；
4. 桌面与手机是两种构图，而不是同一种构图的缩放。

### 1.1 关于「克制」

克制不是什么都不做，而是*只做必要的事*。比如背景里的浮动圆，它们只透过网格线显示，平时几乎察觉不到；只有当光标经过、或者你停下来注视时，网格才会轻轻亮起。

#### 一个小原则

> **注意：** 装饰永远不该和正文抢注意力。悬停在文字、链接或图片上时，网格标注会降到 3% 的不透明度。

这条原则后来被写进了组件里，而不只是停留在设计稿上。

### 1.2 关于「构图」

首页在桌面上是左文右图的双栏，手机上则变成插画铺底、文字居中的单栏。两者共享内容，却各自有完整的节奏。

## 二、技术栈一览

| 部分 | 选择 | 说明 |
| :--- | :---: | ---: |
| 框架 | Astro 7 | 文件即路由，默认零 JS |
| 样式 | Sass / SCSS | 组件内联样式为主 |
| 路由 | `<ClientRouter />` | 页面切换不整页刷新 |
| 工具链 | Vite+ | `vp fmt`、`vp check` |
| 包管理 | Yarn 4 | 沿用 `yarn.lock` |

表格里的三列分别是左对齐、居中和右对齐，用来检查对齐方式是否生效。

### 2.1 页面过渡

站点内的跳转由 Astro 的 ClientRouter 接管，每次导航分成两个阶段：

- **加载阶段**：如果下一页超过 200ms 还没准备好，屏幕中央会出现三个循环脉动的小圆点；
- **过渡阶段**：加载完成后，圆点放大淡出，同时播放目标页面自己的过渡：
  - 首页：从中心展开的圆形光圈；
  - 文章：自上而下的划幕，带标题与编号；
  - 小说：一层白雾和两行诗句。

> 换页前开始动画、换页后再揭开，这是原生跨文档过渡做不到的事。

### 2.2 生命周期

ClientRouter 下，页面脚本只执行一次，因此每个交互都要在 `astro:page-load` 时初始化，并在 `astro:before-swap` 时清理。下面是项目里统一的写法：

```ts
import { onPageLoad } from "../lib/pageLifecycle"

onPageLoad((scope) => {
  const footnote = document.querySelector<HTMLElement>(".site-footnote")
  if (!footnote) return

  // 监听器、定时器和动画帧都挂在 scope 上，换页前自动清理
  scope.listen(window, "scroll", () => update(footnote), { passive: true })
  scope.observe(new ResizeObserver(() => update(footnote)))
})
```

样式方面也有一些不太显眼的细节，比如章节编号的描边会随屏幕宽度变粗：

```scss
.chapter-numeral {
  color: transparent;
  // 1200px 宽时 1px，1800px 起封顶 1.5px
  -webkit-text-stroke: clamp(1px, 100vw / 1200, 1.5px) rgba($light-blue, 0.55);
}
```


## 三、一些设计上的取舍

### 3.1 单位：`svh`、`dvh` 与 `lvh`

手机浏览器的工具栏会随滚动收起和弹出，这让「一屏有多高」变成了一个移动的目标。最后的做法是按用途分开：

- 每屏**占用的滚动距离**用 `svh`，保证停靠点不随工具栏移动；
- 粘性的**内容框**用 `dvh`，让内容跟着屏幕底部走；
- 背景**视频层**直接测量自身尺寸，始终铺满。

~~一开始我想全部换成 `dvh` 一劳永逸~~，后来发现那样每次工具栏收放都会让所有停靠点一起跳动。

### 3.3 键盘与小字

小说页支持键盘浏览：按 <kbd>↓</kbd> 或 <kbd>Space</kbd> 前进一屏，<kbd>↑</kbd> 后退，<kbd>Esc</kbd> 关闭阅读面板。

化学式和上下标也许用不上，但测试总要有：H<sub>2</sub>O、E = mc<sup>2</sup>，以及一段<mark>被标记的重点文字</mark>。

<details>
<summary>展开：为什么网格是 <code>min(10vh, 10vw)</code>？</summary>

背景网格以视口较短边的十分之一为一格，这样横屏与竖屏的格子都是正方形，而且屏幕上大约总能放下十格。网格标注组件也用同一个公式，才能和背景的线条严丝合缝地重合。

</details>
